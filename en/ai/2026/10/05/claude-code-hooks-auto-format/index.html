30 Days of Vibe Coding | Day 22: Hooks — Claude Code's Lifecycle Triggers

Intro

We're about to head into Week 4, which is also the final week of the whole series.

So what are we doing starting this week? I want to introduce the AI's "lifecycle triggers": Hooks.

The idea is that they hook into the AI's lifecycle and run specific commands at specific moments. None of this involves any AI judgment at all — it's pure system-level automation.

The idea behind Hooks: the lifecycle

AI actually has this concept called a "lifecycle." I know a lot of you might be thinking...

"Huh? Lifecycle? AI has a lifecycle too?"

In short, while the AI is working on a task, it goes through certain events, for example:

  • Before a tool runs (PreToolUse)
  • After a tool runs (PostToolUse)
  • Every time the AI finishes responding (Stop)
  • When it needs your attention (Notification)

These four are basically the lifecycle events you'll use the most. When one of them happens, we can attach our own Hook to it, so it automatically runs the command we want.

These Hook settings go in the project's config file, usually in the hooks block of settings.json.

So what's settings.json? We haven't really talked about it so far. It's the AI's config file — permissions, Hooks, and settings like that all live in there. And just like the Skills we covered on Day 15, it comes in two levels:

  • On your computer (~/.claude/settings.json): Shared across all of your own projects.
  • In the project (.claude/settings.json): Only used by this project, and it gets committed along with the project, so your teammates get the same settings when they pull it down.

There's also a .claude/settings.local.json. It lives in the project too, but it's just for you personally and doesn't get committed to Git. We'll use it for the second Hook in a bit.

At this point you might be wondering: how is this any different from just writing a rule in CLAUDE.md?

Roughly speaking, it's the difference between "please do this" and "you have to do this."

Not quite clicking? Earlier we covered CLAUDE.md, the rules and constitution for the AI to read. It gets loaded every time you start a new conversation. But even though we call it a constitution, a set of rules, there's still a good chance it gets forgotten, especially once the Context gets too long. So CLAUDE.md is more of a "please do this" thing — the AI does its best to follow it, but there's no guarantee it remembers every time.

A Hook, on the other hand, is an automated mechanism built at the system level. Whenever the AI performs a certain action or hits a certain event, the Hook fires, every single time, without going through the AI's judgment at all. So it's way more enforceable than CLAUDE.md.

So when do people usually use it? The simplest example is "format a file after it's been changed." Something that has to happen every single time is a great fit for a Hook, and there's no need for the AI to make a judgment call on it.

Comparing the differences

So next we're going to actually build two Hooks: a shared PostToolUse formatting Hook, and a personal Stop desktop notification Hook.

Note

You've probably noticed I keep stressing how important Context is. No matter which plan you're on, or even if you're calling the API directly, the most expensive thing with AI is always tokens, and using your Context wisely.

Build #1: auto-format a file as soon as it's changed

Now let's see what Hooks can actually do, starting with the simplest one: formatting.

First, there's one thing you need to do: create a .claude/hooks folder in the money-note project. This folder is where the Hook scripts go.

Next, we'll install a new package in this project called Prettier. It's a code formatter that tidies up indentation, quotes, semicolons and so on according to a fixed set of rules, so all the code in your project looks consistent. Same as before, open your terminal, go to the project folder, and type:

Bash
npm install -D prettier

Of course, you can also be a little lazy and give the AI this prompt to install it for you:

Text
Please install Prettier in the money-note project and add it to devDependencies.
Note

If your project already has Prettier installed, just skip this step.

Before we paste in any code, here's how this Hook works:

  1. The AI uses the Edit or Write tool to change a file.
  2. The moment the change is done, the PostToolUse event fires, and the AI checks settings.json for any Hook attached to that event.
  3. If there is one, it runs the command in that Hook and hands it a JSON report of "what just happened." The JSON includes which tool was used this time and which file was changed.
  4. Our custom command then receives that JSON, pulls the file path out of it, and runs Prettier on that file.

I drew this out as a flowchart too:

Flowchart

So we need two things:

  • A script that receives the JSON and runs Prettier.
  • A setting that tells the AI "run this script on PostToolUse."

Next, create the file .claude/hooks/format-edited-file.mjs in the project and paste in the following (or, of course, just throw this at the AI and have it create the file for you):

JavaScript
··································import { spawnSync } from 'node:child_process'
import { isAbsolute, relative, resolve } from 'node:path'

let raw = ''
for await (const chunk of process.stdin) raw += chunk

try {
  const input = JSON.parse(raw)
  const filePath = input.tool_input?.file_path
  if (!filePath) process.exit(0)

  const projectRoot = resolve(process.env.CLAUDE_PROJECT_DIR || process.cwd())
  const target = isAbsolute(filePath) ? resolve(filePath) : resolve(projectRoot, filePath)
  const pathFromRoot = relative(projectRoot, target)

  if (pathFromRoot.startsWith('..') || isAbsolute(pathFromRoot)) process.exit(0)

  const prettierBin = resolve(projectRoot, 'node_modules/prettier/bin/prettier.cjs')
  const result = spawnSync(process.execPath, [prettierBin, '--write', '--ignore-unknown', target], {
    cwd: projectRoot,
    stdio: ['ignore', 'inherit', 'inherit'],
  })

  process.exit(result.status ?? 0)
} catch (error) {
  console.error('格式化 Hook 無法讀取輸入：', error.message)
  process.exit(1)
}

You don't need to spend much time on the code above. It basically just does three things:

  • Takes in the JSON the AI hands over in step 3, then finds the file that was changed, which is tool_input.file_path.
  • Checks that the file really is inside the project folder.
  • Runs Prettier on that one file.

Next, we hook the script up in .claude/settings.json, so it runs automatically whenever the PostToolUse event happens:

JSON
····························································································{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node \"${CLAUDE_PROJECT_DIR}/.claude/hooks/format-edited-file.mjs\""
          }
        ]
      }
    ]
  }
}

Pretty short, right? Don't worry, I'll go through it piece by piece:

  • PostToolUse: The lifecycle event, meaning it fires after a tool finishes running.
  • matcher: Sets a filter, so it only fires after the two file-editing tools, Edit and Write, finish. Reading files or running commands won't trigger it.
  • command: The command you want to run. Here we use Node to run the script from earlier. ${CLAUDE_PROJECT_DIR} is a variable Claude Code provides, and it points to the project's root directory.

Once you save, Claude Code should pick up the config change on its own, but to be safe you can restart it once to make sure it really loaded the settings.

So how do we test it? Easy — give the AI this prompt:

Text
Please use the Write tool to create src/hook-test.js with any small function in it. Deliberately mess up the indentation and spacing, leave out the semicolons, and just write it straight in — no need to check or format it.

You should see it write something really messy:

src/hook-test.js with deliberately messy formatting

But... when you actually open src/hook-test.js, you'll find the formatting has already been cleaned up nice and neat.

src/hook-test.js after the Hook automatically cleaned it up

Note

There's a reason I specifically wrote "use the Write tool" in the prompt. The Hook's matcher only looks at the Edit and Write tools. If the AI writes the file out with a Bash command instead (like cat > file), then... the Hook won't run. That's why I deliberately told it to use the Write tool.

Build #2: notify me when it's done

This next Hook is one I actually use myself. I pretty often hand the AI tasks that take a while to run, and I can't just sit there staring at the terminal the whole time, right?! I'm definitely going to use that time for small things that can be interrupted. So I wrote a Stop Hook that pops up a desktop notification every time the AI finishes responding.

Now, a quick heads-up about this example: it's macOS-only, so I don't recommend using it on Windows or Linux, since their desktop notification commands are different. Also, notifications like this are usually more of a "personal" thing, so I'd put it in .claude/settings.local.json, not the shared .claude/settings.json — otherwise your teammates will start getting notifications as soon as they pull the project lol.

So create .claude/settings.local.json and paste in the following:

JSON
····················································································{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"money-note 的任務完成了\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
Note

osascript is a macOS-only command. Also, Stop doesn't have a matcher to set, so you can just write hooks directly here.

One more thing to watch out for: .gitignore usually doesn't exclude .claude/settings.local.json, since it's a file you create by hand. So add it to .gitignore yourself, so you don't accidentally commit it to Git.

Once you've added the Hook above, let's try triggering it. You can send the AI pretty much any prompt, for example:

Text
Hello! How are you today?

If all goes well, you'll get a macOS desktop notification telling you "money-note 的任務完成了" ("the money-note task is done").

The macOS desktop notification that pops up when a task is done

Easy, right? Hooks are really powerful — I've even hooked mine up to my Discord channel.

Hooks are a double-edged sword

Before we finish, there's one more thing I need to point out. Hooks are really powerful, and their value comes from being enforced — but that's also exactly where the risk is.

What do I mean? When a rule in CLAUDE.md has a problem or is written wrong, the AI can use its own judgment to fix it or work around it. But if your Hook has a bug, it'll blow up every single time it fires, and it won't make any judgment calls for you.

So what I'd recommend is: talk it through with the AI, have the AI write the Hook script for you, then test it in your own terminal first. Only after you've confirmed it works should you hook it up. That cuts out a lot of unnecessary trouble.

For example, you can test this script by handing it some JSON with no file path. If everything's fine, it'll exit quietly without any errors:

Bash
printf '%s' '{"tool_input":{}}' | node .claude/hooks/format-edited-file.mjs

Wrapping up

That pretty much covers this one, so let's do a quick summary again:

  • A Hook is a mechanism attached to the AI's lifecycle. It runs as soon as the event happens, without going through the AI's judgment. CLAUDE.md is "please do this," a Hook is "you have to do this."
  • Hook settings go in the hooks block of settings.json. Shared ones go in the project's .claude/settings.json and get committed with it. Personal ones (like desktop notifications) go in .claude/settings.local.json — remember to add that file to .gitignore yourself.
  • matcher decides which tools trigger the Hook. This time it only watches Edit and Write, so the AI writing a file with Bash won't trigger it.
  • Hooks are enforced, so if the command is broken, it blows up every time it fires. Test it in the terminal before hooking it up.

Tomorrow we'll talk about testing. Remember the code Day 14 said you could let slide for now because a mistake there wouldn't hurt much? It's time someone kept an eye on it for you.

I hope this post gave you a better feel for Hooks.
