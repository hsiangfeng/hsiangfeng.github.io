老闆不會教你的 Vibe Coding 實戰 30 天｜Day 2：Vibe Coding 是什麼？換一種懂法

前言

今天我們先來了解一下「Vibe Coding」這個詞的由來，還有它背後的意涵，畢竟我們整個系列都是建立在這個詞上面，那不去認識一下似乎不太對吧？依照我的寫文慣例，動手之前我都會希望先搞懂這個背景知識的來源。

當然，你也可以完全不理會這個詞的來歷。

只是我可以跟你偷偷說，很多人對 Vibe Coding 的想像是「躺著讓 AI 幫自動開發」，所以如果誤會如果不先解開，後面 28 天你可能會發現自己認知中的 Vibe Coding 跟你想像的完全不同唷～

Vibe Coding 是怎麼來的？

Vibe Coding 這個詞是 Andrej Karpathy（安德烈·卡帕西） 提出來的，他是前 Tesla 的 AI 總監、OpenAI 的創始成員之一，看到 Tesla + OpenAI 應該就可以知道這位人物在 AI 圈內是一位重量級人物，他在 2025 年 2 月發了一則 X 貼文：

X 貼文

There's a new kind of coding I call "vibe coding", where you fully give in to the vibes, embrace exponentials, and forget that the code even exists.

英文很難懂嗎？別擔心，這句話簡單來講是再說...

現在有一種全新的開發模式，我稱為「Vibe Coding（憑感覺寫程式）」，你只需要順著感覺走就好，你甚至會忘記程式碼的存在。

看原文的意思你會感覺到 Andrej Karpathy 當時是用一種帶點開玩笑、自嘲的方式在講這件事，也就是跟 AI 用講的溝通、看到錯誤訊息就整段貼給它、程式碼看都不看，拿來做週末小專案很快樂，他自己也說這種做法「mostly works（大致上能用）」。

Note

「mostly works」這單字其實帶有保留意味，也就是大致上能用，可是能不能穩定、可靠、可維護，這些都是未知數。

但誰也沒想到後來「Vibe Coding」這個詞的成長速度遠遠超過原本的意思，從帶點自嘲的貼文，變成泛指用自然語言叫 AI 幫你開發軟體的統稱，最後連 Collins 字典都把它選為 2025 年度詞彙（笑）。

不用會寫程式，是真的嗎？

我認為這句話一半真、一半假，而且假的那一半剛好是那個專案能不能成功的關鍵。

什麼意思呢？

  • 真的部分： 寫程式碼的門檻確實降低了，以前你要做一個小專案，可能要花上好幾天甚至幾週去學語法、背 API、查文件，現在你只要會打字，AI 就能幫你把程式碼寫出來。
  • 假的部分： 懂跟判斷的能力並沒有消失，雖然你不再需要一行一行把程式寫出來，可是你需要另外三種能力：描述力、驗收力、拆解力。

這三件事情其實在平常生活中就是很常見的能力，只是因為 AI 的關係被放大了：

  • 描述力：把腦袋中「我想要做一個記帳軟體」的模糊想法，變成 AI 能夠實際動工的具體需求，而不是隨便一句話丟給它就結束。
  • 驗收力：它做完之後，你要有辦法驗證東西是不是你要的、有沒有順便弄壞別的東西，而不是 AI 說「做完」就結束。
  • 拆解力：把一個大目標切成一次做得完、錯了找得到的小步驟，而不是丟一個大目標全靠它自己發揮。

看到這邊，我也想問你一個問題，也就是叫 AI 做一個功能，它非常快速且劈哩啪啦改了一堆檔案，雖然畫面看起來能動，但你心裡完全沒有底跟把握。

為什麼呢？其實就是你心理無法確定底下三件事：

  • 它做了什麼？
  • 做對了嗎？
  • 功能正常嗎?

因此這系列就是訓練你這三件事。

Note

這也是為什麼我會說 Vibe Coding「不是不用懂，是換一種懂法」。 因此，門檻並沒有消失，而是從手要會寫，變成了腦要會判斷，而後者的學習曲線我認為相對友善就是了（吧？）。

AI Coding 工具的三種型態

搞懂了 Vibe Coding 小故事之後，接著我們也來了解一下即將使用的工具。

市面上的 AI 工具琳瑯滿目，但 AI 可以幫助你做到什麼樣的程度開發，光這件事就可以把這些工具分成三種形態：

AI Coding 工具光譜：自動補全、問答聊天、AI Agent

  • 第一種自動補全： 你打一小段話，後面 AI 幫你自動補全後面的文字，最知名的代表就是 GitHub Copilot，這種主導權完全在你手上，只是讓你打字速度快一點而已。
  • 第二種問答聊天： 你把問題或程式碼丟給 AI，AI 會給你答案跟範例，但你要自己手動把程式碼貼過去，感覺就像 AI 是一名顧問，但實際面對跟處理事情的人還是你。
  • 第三種 AI Agent： 你給它一個任務、需求，它會自己讀你的專案、自己決定要改哪些檔案、自己執行指令等等，一直到做完才跟你回報結果，這過程你變成了只需要出張嘴的人（ 跟老闆一樣 ），而 Claude Code、Codex 這些工具就是這種型態。

介紹到這邊，基本上你只需要知道有這三種型態就好，因為這三種型態的差異，會直接影響你在 Vibe Coding 的體驗。

那...Vibe Coding 是上面哪一個呢？答案當然是第三種「AI Agent」，

畢竟前兩個你還要自己碰程式碼，只有 AI Agent 才是真正的「你說、它做」的模式。

Note

Claude Code、Codex 這類我都統稱 AI Agent。

練習一個驗收題

明天要來安裝我們的 AI Agent 工具了（Claude Code），但在那之前我希望你思考一個問題：

如果你叫 AI 做一個「新增支出」的功能，怎麼樣才算真的完成？

我建議你花點時間思考一下這個問題，千萬不要想一個很抽象的答案，像是...「可以輸入金額並成功送出」這種答案，因未這實在太抽象，你至少要列出三～四種條件，可以看得到、可以驗收的條件，像是：

  • 金額欄位是空白或為 0 時，不能送出
  • 新增支出 120 元午餐後，支出清單會立刻出現剛剛新增的支出資料
  • 重新整理頁面後，資料還在，不會因為重新整理而消失
  • 手機寬度下不用左右滾動、捲動就能完成輸入

上面這些就是一個驗收功能與畫面的最小單位。

這些都是在請 AI 開始做事之前，就先寫好「做完要看到什麼」，進而避免出現「它說完成了，但我卻無法掌握它完成了什麼」的狀況。

Note

如果你是相關工程背景，你會發現這觀念很像所謂的先寫測試再寫程式（TDD，Test Driven Development）。

為什麼這個系列用 Claude Code？

講了那麼多，終於要來談一下為什麼我會挑選 Claude Code 當作這個系列的實戰工具。

其實很簡單，Claude Code 可以說是 AI Agent 的最佳實踐之一。

什麼意思呢？舉例來講...

  1. 你可能聽過 MCP 這個名詞，它是 Claude Code 背後的公司 Anthropic 在 2024 年推出的開放協定
  2. Skills、Subagents 也是 Anthropic 推出的

這些名詞現在看不懂完全沒關係，它們會在後面的章節輪流登場，所以作為 Vibe Coding 的實戰工具來講，我認為選擇 Claude Code 是滿合理的（當然有一部分也是因為我自己最常使用 Claude Code）。

如果你有自己習慣的 AI Agent 工具，我認為也沒關係，因為 AI 廠商各家都是抄來抄去的，Vibe Coding 的觀念本身並不綁工具，所以就算我這系列是使用 Claude Code 示範，之後你換到 Codex 或是 Gemini 等工具，這套觀念一樣用得上。

Note

Claude Code 是 Anthropic 官方推出的產品之一，其他還有網頁版的 Claude（claude.ai）跟 Claude Desktop 等等產品。

另外，Claude Code 可以說是工程師最習慣的產品（應該吧？），畢竟它直接運作於終端機內，你可以在終端機中很自然的用中文跟它講話，而它的工作方式，在官方中也描述得很直白，它會先...

  1. 蒐集資訊（讀你的專案、搞清楚現況）
  2. 然後動手做（改檔案、跑指令）
  3. 最後驗證結果（確認自己做的東西能動）

但你可以注意一件事情，它在做任何事情時，都必定會 留下紀錄，像是讀了哪個檔、改了哪一段、跑了什麼指令，那這些紀錄該怎麼看？什麼時候該喊停？這就是後面章節要練的基本功，到時候我們會盯著它改的每一行東看西看。

Note

不要再問我「為什麼不使用 XXX 而是用 Claude Code 」這種問題了，因為只要你掌握好核心 Vibe Coding 的觀念，其他工具都是可以互通的。

把 AI 當成一個知識淵博的助手、實習生

這一篇快結束了，最後我想要給你一個觀念：

請把 AI Agent 當成一個知識淵博的助手、實習生，而不是全知全能的神，你不講清楚它只能臆測。

這個觀念重點在於，你請了一位助手來幫你做事情，但你絕對不會只丟一句「我想做記帳軟體」就跑去睡覺吧？

你肯定會把需求講清楚、陪他一起把大任務拆小、做完檢查他的成果，重要的核心功能你還會問他怎麼做對吧？

這些面對這位助手、實習生的溝通、拆解等技巧，剛剛好就是 Vibe Coding 實戰中你最需要的能力。

你會發現接下來 28 天的每個工具、每個流程，其實都只是在把這些常識、知識落地而已。

反過來講，如果你只是丟一句話「我想做記帳軟體」就跑去睡覺，那你有 8 成機率會產出你不想要的東西，接著你就會罵 AI 笨，然後你就會開始懷疑是不是自己不適合做這件事，但其實這些只是你沒把需求講清楚、沒定義好驗收標準、沒拆解任務而已。

結語

ok，最後的最後，一樣總結一下吧。

所以 Vibe Coding 到底是什麼？

  • 一種你可以用自然語言描述、AI 動手開發的方式，Andrej Karpathy 在 2025 年提出，紅到變成年度詞彙。
  • 不用「寫」程式是真的，不用「懂」是假的，你更需要的能力從寫語法變成描述、驗收、拆解。
  • 只要把核心觀念掌握，不管用哪一套 AI Agent 工具都可以實戰。
  • 請把 AI 當成一個知識淵博的助手、實習生，而不是要求它當全知的神。
